## Hosts and authentication

| Base URL | Operations |
|---|---|
| `https://pro.api.serversmtp.com/api/v2` | Management API |
| `https://api.turbo-smtp.com/api/v2` | `POST /mail/send`, global |
| `https://api.eu.turbo-smtp.com/api/v2` | `POST /mail/send`, EU |

Both Consumer headers are required for sending. Management operations generally accept the same pair with **Statistics & Management APIs** (`APIS`) enabled. Consumer-key management and password changes require a session API key instead. The [authentication guide](/api-reference/authentication) explains these exceptions and the current limitation of legacy `/authorize` login.

```bash Read analytics
curl --get 'https://pro.api.serversmtp.com/api/v2/analytics' \
  -H 'consumerKey: YOUR_CONSUMER_KEY' \
  -H 'consumerSecret: YOUR_CONSUMER_SECRET' \
  --data-urlencode 'from=2026-10-01' \
  --data-urlencode 'to=2026-10-27'
```

See [base URLs and SMTP settings](/api-reference/base-urls) for global and EU hosts. turboSMTP is an Italian company with European sending infrastructure.

## Request and response formats

Use `Content-Type: application/json` when sending a JSON body. Some operations use multipart file uploads, and CSV exports return CSV rather than JSON. Check each endpoint's format before copying an example.

Analytics and suppressions use date filters in `YYYY-MM-DD` format. Send recipients as comma-separated strings in `to`, `cc`, and `bcc`; attachments are an array of objects. List endpoints commonly return an object containing `count` and `results`, rather than a bare array.
