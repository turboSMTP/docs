The turboSMTP REST API v2 gives you programmatic access to the full platform — send transactional and marketing emails, manage bounce and unsubscribe lists, validate email addresses before you send, query delivery analytics, configure alerts, and administer sub-accounts, all over HTTPS with JSON bodies. Every feature available in the [dashboard](https://dashboard.serversmtp.com) is also available through the API, so you can build automated workflows, integrate turboSMTP into your own applications, and keep your sending infrastructure entirely under your control.

## Base URLs

Different operations use different base URLs. Make sure you target the correct host for each request — using the wrong host is the most common cause of unexpected `401` errors.

| Base URL | Used for |
|---|---|
| `https://pro.api.serversmtp.com/api/v2` | All endpoints **except** `/mail/send` |
| `https://api.turbo-smtp.com/api/v2` | `POST /mail/send` — global infrastructure |
| `https://api.eu.turbo-smtp.com/api/v2` | `POST /mail/send` — EU infrastructure (GDPR) |

See the [Base URLs](/api-reference/base-urls) page for a full explanation of when to use each host, including guidance on EU data residency.

## Data Format

All request and response bodies use JSON. Include the `Content-Type: application/json` header on every request that sends a body. Responses always return `Content-Type: application/json` as well. Boolean values are native JSON booleans (`true` / `false`), dates are ISO 8601 strings, and arrays are used for multi-value fields such as recipients and attachments.

```http Example request headers
POST https://pro.api.serversmtp.com/api/v2/authorize
Content-Type: application/json
```

## Authentication Summary

turboSMTP's API supports two authentication methods depending on the operation you are performing:

- **API Key** — obtained by calling `POST /authorize` with your account email and password. Pass the returned key as `Authorization: <key>` (raw key, no `Bearer` prefix). Used for account management, analytics, suppressions, and all endpoints except `/mail/send`. Keys expire after 2 hours by default.
- **Consumer Key / Secret** — a permanent key pair created in the dashboard or via the API. Pass them as `consumerKey: <key>` and `consumerSecret: <secret>` headers. **Required** for `POST /mail/send`. Supports IP restrictions and can be revoked individually.

See the [Authentication](/api-reference/authentication) page for full details on obtaining keys, revoking them, and choosing the right method.

<Note>
  The API v1.0 is deprecated and has been shut down. All integrations must use the v2 endpoints documented here. If you have existing code targeting `dashboard.serversmtp.com/api/...`, migrate to `pro.api.serversmtp.com/api/v2/...` immediately.
</Note>

## SDKs

turboSMTP maintains official SDKs on GitHub to speed up integration in common languages:

- **C#** — [github.com/turboSMTP/turboSMTP-csharp](https://github.com/turboSMTP/turboSMTP-csharp)
- **PHP** — [github.com/turboSMTP/turboSMTP-php](https://github.com/turboSMTP/turboSMTP-php)

Each SDK wraps the REST API with typed models and handles authentication, serialization, and error handling for you. Refer to the README in each repository for installation instructions and usage examples.

## Rate Limits

The `/authorize` endpoint is rate-limited to prevent abuse. Do not call it before every API request — instead, cache the returned API key and reuse it for its full lifetime (2 hours by default, or indefinitely with `no_expire: true`). For production integrations that send email, use Consumer Key / Secret pairs, which are permanent and not subject to the same rate limits as `/authorize`.
