To migrate from SendGrid, update your SMTP settings or convert v3 Mail Send requests to turboSMTP's JSON format. This guide also covers DNS, suppressions, and webhooks. Global and EU sending hosts are available; review processing terms for your regional requirements.

<Note>
  SendGrid settings checked on 27 October 2026 against Twilio's [SMTP guide](https://www.twilio.com/docs/sendgrid/for-developers/sending-email/integrating-with-the-smtp-api) and [Mail Send reference](https://www.twilio.com/docs/sendgrid/api-reference/mail-send/mail-send). SendGrid also has regional EU hosts; use your existing region when reviewing these examples.
</Note>

## Before you start

<Steps>
  <Step title="Create a turboSMTP account">
    [Sign up for free](https://serversmtp.com/en/signup) and create a Consumer Key and Consumer Secret. See [API Keys](/get-started/api-keys).
  </Step>
  <Step title="Authenticate your sending domain">
    Merge turboSMTP's SPF include into your existing single SPF record and add its DKIM record. Keep SendGrid authorized until migration and queued delivery are complete. See [SPF, DKIM, and DMARC](/deliverability/spf-dkim-dmarc).
  </Step>
  <Step title="Export your suppressions">
    Export bounces, unsubscribes, and spam reports from SendGrid and use `POST /suppressions/import` to add them to turboSMTP. Preserve subscription-group preferences in your application when an account-wide suppression would be too broad. See the [Suppressions API](/api-reference/suppressions).
  </Step>
</Steps>

## Option 1: Switch SMTP credentials

If your application, CMS, or framework sends through `smtp.sendgrid.net`, replace these settings:

| Setting | SendGrid | turboSMTP |
| --- | --- | --- |
| Host | `smtp.sendgrid.net` | `pro.turbo-smtp.com` (EU: `pro.eu.turbo-smtp.com`) |
| Port and encryption | 587 with STARTTLS | 587 or 2525 with STARTTLS; 465 or 25025 with implicit TLS; 25 also available |
| Username | `apikey` | Your turboSMTP Consumer Key |
| Password | Your SendGrid API key | Your turboSMTP Consumer Secret |

<CodeGroup>

```bash SendGrid
SMTP_HOST=smtp.sendgrid.net
SMTP_PORT=587
SMTP_USER=apikey
SMTP_PASS=YOUR_SENDGRID_API_KEY
```

```bash turboSMTP
SMTP_HOST=pro.eu.turbo-smtp.com
SMTP_PORT=587
SMTP_USER=YOUR_CONSUMER_KEY
SMTP_PASS=YOUR_CONSUMER_SECRET
```

```bash Diff nocopy
SMTP_HOST=smtp.sendgrid.net # [!code --]
SMTP_HOST=pro.eu.turbo-smtp.com # [!code ++]
SMTP_PORT=587
SMTP_USER=apikey # [!code --]
SMTP_USER=YOUR_CONSUMER_KEY # [!code ++]
SMTP_PASS=YOUR_SENDGRID_API_KEY # [!code --]
SMTP_PASS=YOUR_CONSUMER_SECRET # [!code ++]
```

</CodeGroup>

<Note>
  Require STARTTLS for these port 587 examples. Global and EU support the same ports and TLS modes. Enable **SMTP Sending** on your key and check any IP restrictions. See [SMTP Setup](/get-started/smtp-configuration).
</Note>

## Option 2: Convert API calls

Replace `https://api.sendgrid.com/v3/mail/send` with `https://api.turbo-smtp.com/api/v2/mail/send` (EU: `https://api.eu.turbo-smtp.com/api/v2/mail/send`) and send your credentials as headers instead of a Bearer token.

**1. Change the endpoint and authentication headers:**

<CodeGroup>

```bash SendGrid
curl --request POST \
  --url https://api.sendgrid.com/v3/mail/send \
  --header 'Authorization: Bearer YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data @payload.json
```

```bash turboSMTP
curl --request POST \
  --url https://api.eu.turbo-smtp.com/api/v2/mail/send \
  --header 'consumerKey: YOUR_CONSUMER_KEY' \
  --header 'consumerSecret: YOUR_CONSUMER_SECRET' \
  --header 'Content-Type: application/json' \
  --data @payload.json
```

```bash Diff nocopy
curl --request POST \
  --url https://api.sendgrid.com/v3/mail/send \ # [!code --]
  --url https://api.eu.turbo-smtp.com/api/v2/mail/send \ # [!code ++]
  --header 'Authorization: Bearer YOUR_API_KEY' \ # [!code --]
  --header 'consumerKey: YOUR_CONSUMER_KEY' \ # [!code ++]
  --header 'consumerSecret: YOUR_CONSUMER_SECRET' \ # [!code ++]
  --header 'Content-Type: application/json' \
  --data @payload.json
```

</CodeGroup>

**2. Flatten the payload:**

This example maps one personalization. For separate messages, per-recipient subjects, templates, or substitutions, render and send each intended message separately. Flattening several personalizations into one recipient list can expose recipients or change the message they receive.

<CodeGroup>

```json SendGrid
{
  "personalizations": [{
    "to": [{ "email": "recipient@example.com" }],
    "cc": [{ "email": "team@example.com" }]
  }],
  "from": { "email": "you@yourdomain.com" },
  "subject": "Your order has shipped",
  "content": [
    { "type": "text/plain", "value": "Your order is on its way." },
    { "type": "text/html", "value": "<p>Your order is on its way.</p>" }
  ]
}
```

```json turboSMTP
{
  "from": "you@yourdomain.com",
  "to": "recipient@example.com",
  "cc": "team@example.com",
  "subject": "Your order has shipped",
  "content": "Your order is on its way.",
  "html_content": "<p>Your order is on its way.</p>"
}
```

```json Diff nocopy
{
  "personalizations": [{ // [!code --:5]
    "to": [{ "email": "recipient@example.com" }],
    "cc": [{ "email": "team@example.com" }]
  }],

  "from": "you@yourdomain.com", // [!code ++:3]

}
```

</CodeGroup>

<Warning>
  `/mail/send` authenticates only with `consumerKey` and `consumerSecret`. It ignores `Authorization`, so a request carrying only that header is refused. Enable **HTTP API Sending** on your key.
</Warning>

### Field mapping

| SendGrid v3 | turboSMTP | Notes |
| --- | --- | --- |
| `personalizations[].to[].email` | `to` | Comma-separated string of addresses |
| `personalizations[].cc` / `bcc` | `cc` / `bcc` | Comma-separated strings |
| `from.email` and `from.name` | `from` | Address, optionally `Name <address>` |
| `subject` | `subject` | Unchanged |
| `content[]` with `text/plain` | `content` | Plain text body |
| `content[]` with `text/html` | `html_content` | HTML body |
| `attachments[]` (`content`, `filename`, `type`) | `attachments[]` (`content`, `name`, `type`) | Base64 content; the whole email must be less than 24 MB. See [Attachments](/sending/attachments) |
| `headers` | `custom_headers` | Object of header names and values |
| `custom_args` | No direct equivalent for a metadata map | Store metadata in your application; use a UUID `reference_id` for correlation |

A successful request returns `{"message":"OK","mid":...}`. This acknowledges acceptance, not delivery. Store `mid` or your UUID `reference_id` to match later events. Base64 adds roughly one third to attachment data before MIME overhead; 24 MB is not a raw-file allowance.

## Replace the Event Webhook

Configure a turboSMTP [webhook](/analytics/webhooks) callback and map SendGrid event names to turboSMTP's delivery events (`PROCESSED`, `DROPPED`, `DELIVERED`, `DEFERRED`, `BOUNCED`) and engagement events (`OPENED`, `CLICKED`, `UNSUBSCRIBED`, `REPORT`).

turboSMTP requests are unsigned. Replace SendGrid signature verification with endpoint protection appropriate for turboSMTP, such as HTTP Basic authentication. Check enabled events and plan availability under **Settings → Notifications → Webhooks → Edit**. Free and Basic include a 30-day webhook demo; settings changes can take up to one hour. Symfony users can check the [upcoming Mailer bridge](/integrations/symfony-mailer).

## Cut over safely

<Steps>
  <Step title="Send a test">
    Send to an internal address and confirm it arrives with SPF and DKIM passing.
  </Step>
  <Step title="Ramp up gradually">
    Route a small share of traffic to turboSMTP and compare delivery in the [statistics dashboard](/analytics/statistics-dashboard).
  </Step>
  <Step title="Switch fully and clean up DNS">
    Move all traffic and sync new opt-outs. After SendGrid's queue has drained, remove only the DNS records and SPF mechanisms no longer needed by another service.
  </Step>
</Steps>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="How long does a SendGrid to turboSMTP migration take?">
    It depends on your DNS access, application features, templates, suppression data, and webhook consumers. Test each sending flow before moving production traffic.
  </Accordion>

  <Accordion title="Do I need to remove SendGrid's DNS records first?">
    No. Keep both providers authorized within one SPF record and retain their DKIM records until cutover and queued delivery are complete.
  </Accordion>

  <Accordion title="Can turboSMTP help with my migration?">
    [Contact support](https://serversmtp.com/contact-us/) to discuss your migration. Available support channels depend on your plan.
  </Accordion>
</AccordionGroup>
