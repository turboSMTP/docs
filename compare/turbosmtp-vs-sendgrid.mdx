turboSMTP and Twilio SendGrid both offer SMTP and HTTP email APIs with Global and EU endpoints. The main integration differences are authentication, API payloads, and regional setup.

## At a glance

| Setting | turboSMTP | Twilio SendGrid |
| --- | --- | --- |
| **Global SMTP host** | `pro.turbo-smtp.com` | `smtp.sendgrid.net` |
| **EU SMTP host** | `pro.eu.turbo-smtp.com` | `smtp.eu.sendgrid.net` |
| **SMTP username** | Consumer Key | Literal string `apikey` |
| **SMTP password** | Consumer Secret | API key |
| **SMTP ports** | 587 / 2525 with STARTTLS; 465 / 25025 with implicit TLS; 25 also available | 25 / 587 / 2525 with STARTTLS; 465 with implicit TLS |
| **Send API** | `POST /api/v2/mail/send` | `POST /v3/mail/send` |
| **EU API host** | `api.eu.turbo-smtp.com` | `api.eu.sendgrid.com` |
| **API authentication** | `consumerKey` and `consumerSecret` headers | `Authorization: Bearer <API_KEY>` |
| **Request format** | Flat JSON fields | JSON with `personalizations` and typed `content` arrays |

<Note>
  Verified on 27 October 2026 against Twilio's [SMTP integration guide](https://www.twilio.com/docs/sendgrid/for-developers/sending-email/integrating-with-the-smtp-api) and [Mail Send reference](https://www.twilio.com/docs/sendgrid/api-reference/mail-send/mail-send). SendGrid EU sending requires Pro or above, an EU IP, and an EU subuser. Check the [current regional setup requirements](https://help.twilio.com/articles/47588342964379) before configuring it.
</Note>

## Regional setup and plans

Choose turboSMTP's [Global or EU sending endpoint](/api-reference/base-urls) for your configuration. An EU endpoint alone does not establish the location of every account record or onward delivery to recipients; review the provider's processing terms for your requirements.

For turboSMTP allowances, see [pricing](https://serversmtp.com/pricing/). Webhooks have a 30-day demo on Free and Basic, and individual events can be disabled for an account. Chat and ticket support are listed for Free and Basic; Pro and Enterprise also list phone support.

## API payloads

The examples below represent one message. Preserve application behavior when migrating multiple SendGrid personalizations, templates, substitutions, or per-recipient metadata.

<CodeGroup>

```json turboSMTP
{
  "from": "you@yourdomain.com",
  "to": "recipient@example.com",
  "subject": "Hello, World!",
  "content": "Heya!",
  "html_content": "<p>Heya!</p>"
}
```

```json SendGrid
{
  "personalizations": [{ "to": [{ "email": "recipient@example.com" }] }],
  "from": { "email": "you@yourdomain.com" },
  "subject": "Hello, World!",
  "content": [
    { "type": "text/plain", "value": "Heya!" },
    { "type": "text/html", "value": "<p>Heya!</p>" }
  ]
}
```

</CodeGroup>

## Switching from SendGrid

Update SMTP host and credentials while preserving the matching TLS mode. API integrations need new authentication headers and payload fields. Follow the [SendGrid migration guide](/migrate/from-sendgrid) for DNS, suppressions, and webhook changes.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do both providers offer EU sending?">
    Yes. Use the EU endpoints and satisfy the provider's regional setup requirements. Review contractual processing terms separately from endpoint selection.
  </Accordion>
  <Accordion title="Can I keep my existing SMTP code?">
    Usually, if your library supports custom SMTP settings. Change the host, username, and password, check TLS, and test the application's sending flow.
  </Accordion>
  <Accordion title="Are the webhooks interchangeable?">
    No. Payloads, event names, authentication, and retry behavior differ. turboSMTP webhooks are unsigned. See the [webhook guide](/analytics/webhooks) before adapting a SendGrid consumer.
  </Accordion>
  <Accordion title="Can I test before switching?">
    Yes. Check the current [free plan terms](/get-started/free-trial), then test a small share of traffic before cutover.
  </Accordion>
</AccordionGroup>
